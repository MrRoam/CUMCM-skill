# 歧义与依赖：需要时展开

以下处理方法根据培训会议知识整理，含面向实际工作的整理补充。目的在于减少解错问题的风险，不要求每次遍历所有情形。

## 一处歧义如何处理

先抄准有分歧的词句及位置，再用具体对象写出解释差别。检查附件说明、同题其他段落、量纲及题目示例能否消解。不要仅凭往届同类题的做法判断当前题意。

可以按影响选择处理强度：

- **改变研究对象或可行域**：如允许区间、信息可得时刻、线段与直线的区别。应先查清；查不清就保留解释分支，并标明哪些工作依赖裁决。
- **改变评价口径**：如总和、平均、并集、同时满足或分别满足。用最小例子显示答案会如何不同，再确定可执行定义。
- **待估参数**：题目允许估计时，说明它进入哪个关系、现有范围是否足以作出判断，以及不同范围会不会改变可行性或路线。不能因为它“只是一个参数”就认定影响小，也不把“数值未知”自动判为无法审题。
- **影响可能有限的简化**：写明忽略因素、简化作用和理由。没有量级或边界依据时，只能称工作假设，不能称已证明无影响。

如果检查只能形成合理推断，记录“当前工作解释”及理由；用户已经给出的明确裁决应保留。后续证据推翻它时，指出受影响的小问和输出再更新。

缺口发现与影响判断是两件事。审题应进一步讲清为什么需要该信息、补到什么程度能支持眼前判断；具体值、原始出处和补全状态由已有数据记录承接。更多例子见 [关键条件与题眼](key-conditions.md)。

## 小问依赖看传递的内容

| 题目关系 | 需要说清楚 | 容易误读的地方 |
|---|---|---|
| 给定方案计算 → 改变方案优化 | 哪个评价关系可复用，哪些给定量变成决策量 | 把前问的具体参数误当成后问不可修改的条件 |
| 单对象 → 多对象 | 单体关系之外是否存在重叠、耦合或共享资源 | 把各对象效果或最优方案直接相加 |
| 简化条件 → 放宽条件 | 哪条前提变化，前问哪些关系仍适用 | 无说明地沿用失效假设 |
| 关系分析 → 行动决策 | 前问输出是否足够，还缺什么目标、代价或约束 | 有了相关性或分组就当作已有最优决策 |
| 历史解释 → 未来预测 | 哪些输入在预测时可得，面向原个体还是新个体 | 将全数据拟合结果当成对未来表现的证明 |
| 共用附件的若干问 | 共用哪些数据定义，是否真的等待前问结果 | 把共用输入误认成串行依赖 |

已有项目需要多人接用时，保持同一套对象、单位和判定用语。这里只形成必要接口：输入是什么、输出是什么、条件是什么；不为审题阶段设计完整代码架构。

## 审查已有拆解时

先看是否回答了全部被要求的小问，再检查关键名词、数值、约束和依赖能否追溯。反馈应包含“原拆解的位置、与原题的差别、会影响什么、建议如何改”；单纯换标题或措辞不算审题发现。

正确内容直接保留。若原题暂缺，说明只能查内部一致性，继续查单位、定义冲突和依赖循环，但不能宣称已对照原题确认。
