# Evidence boundaries

Use this file only to calibrate a recommendation or explain why the Skill does not impose a fixed template.

## Evidence priority

1. Current national CUMCM rule.
2. Applicable regional and school notice.
3. User-provided problem, data, code, and approved decisions.
4. Cross-paper tendencies and competition-writing research.
5. Individual examples and aesthetic preferences.

Only levels 1–2 create format obligations. Levels 4–5 suggest options.

## Corpus findings that may guide, never prescribe

The local audited corpus contains 81 recognized papers and 3975 pages from 2018 and 2020–2025. All pages were extracted; key abstract/body pages and all 26 low-OCR-score pages were visually reviewed.

- Median core length was 24 pages, but problem types varied materially.
- 75/81 papers used level-2 numbered headings and 71/81 used level 3 or deeper; maximum depth had median 3. This supports dependency-based hierarchy, not a mandatory depth.
- Across 11146 filtered body paragraphs, median length was 55 characters and 71.6% contained one sentence. These are extraction-dependent observations, not targets.
- Caption extraction found median 15 figures and 7 tables per paper. Independent figure counting agreed weakly, so exact figure counts are medium-confidence.
- Most core pages used little color. Blue/blue-gray/cyan are optional observed tendencies; page-level red was contaminated by watermarks.
- Abstract text had median 1076 extracted characters, while the only national hard boundary is the abstract page's one-page principle.

There is no non-award comparison group. Do not claim that these tendencies cause awards.

## Skill-design evidence applied here

The design follows recurring patterns from the Agent Skills specification, OpenAI Skill Creator, cross-domain first-party Skills, SkillsBench, public research-paper workflows, and researcher/user reports: precise discovery, progressive disclosure, evidence before prose, stage receipts, author approval for scientific judgment, deterministic checks, and rendered-output verification.

The same sources also warn against overlapping skills, duplicated instructions, large always-loaded files, unverified third-party rules, and treating generated prose as evidence. This Skill therefore keeps each rule in one runtime location and routes conditional detail to one reference.
