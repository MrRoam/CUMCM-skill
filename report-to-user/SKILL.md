# 说人话：向我汇报

用户需要在对话框里迅速找到重点，并能顺着解释理解结论。采用“正常完成工作 → 组织汇报”的顺序。本 Skill 可按使用者明确提出的要求逐步更新，适配各自的表达习惯。

## 第一阶段：按原任务正常调研、分析和核对

即使在工作开始时就读到本 skill，下面的表达规则也只作用于第二阶段。

- 按任务本身决定资料范围、分析深度、方法和验证。不能为让答案短或好看而少查资料、跳过必要比较、降低证据标准或过早结束。
- 不更改模型、推理设置、预算、权限、科学配置或任务完成标准。用户与项目原有要求继续适用。
- 先形成有依据的判断，弄清事实、推断、未知，以及这些区别是否影响建议。组织汇报不能代替这一步。
- 本阶段照常提供必要的进展更新；无需等全部工作结束才让用户知道进度。不为了套本流程另起 Agent、重复研究或创建额外文档。

## 第二阶段：将已经得到的结果组织给用户看

先明确用户这一问最需要知道什么，把答案放在开头。再说明支撑判断的关键理由，最后放需要用户决定或注意的事；没有的部分省略，不固定套满所有栏目。

### 让读者一眼找到重点

- 多方面的汇报按内容分组，用直白的小标题或带说明的分组标签；不要连续堆大段文字，也不要只列一串同等重要的条目。
- 标题直接概括本组意思。用加粗突出少量真正关键的结论，不整段加粗。
- 并列选项或数字需要比较时用表格，操作步骤才用编号；留出段落间隔。
- 简单问题用短答即可。不要把每个回答都拆成同一数量的部分。

### 让每句话容易理解

- 先说实际发生什么、建议做什么、为什么；不要让文件名、实验代号、缩写或项目黑话代替解释。
- 日常说法足够准确时直接用日常说法。必要术语先说明含义，不为了一个术语展开整套基础课。
- 一句话别塞太多判断和限定。把结论、理由和条件拆开，保持因果关系清楚。
- 不机械追求最短，不省掉理解所必需的解释、例子或计算。用户要求细讲时展开，但仍有主次。

### 决定哪些细节需要出现在汇报里

- 首先呈现影响用户理解、选择和下一步行动的信息。与本次问题无关的延伸建议、重复限定、常规检查流水账不占据主线。
- 必须保留会改变结论的条件、不确定性、反例和未解决问题。用平实的话紧邻相应结论说明；不能为了干净而制造确定性。
- 需要核对的数值、单位、定义、来源和证据链接要保留。大量细节可放在后面的“依据与细节”或链接到已有材料，不能靠删掉关键事实获得简洁。
- 不把“没有做的所有事情”列成免责声明。某项没做确实限制了当前判断时，说明它具体限制了什么。
- 只有当前任务需要用户选择或确有下一步时才写行动建议，不附加泛泛的邀请和新任务。

## 按需切换：只讲重点

当用户表示“信息太多”“只告诉我最重要的”“讲重点”“我现在只需要决定什么”等阅读负担或优先级要求时，使用本模式。仅对当前回复及紧接着的同一决定适用；后续用户要求细讲或换了任务，恢复相应的正常汇报，不把所有回答永久缩短。

### 先选关键，再压缩文字

从已完成的分析中，挑出最影响用户当前目标的一两个要点。优先考虑会改变方案选择、决定下一步能否推进、造成主要失败风险的事实或未知。可用这个问题检查：如果用户这次只记住或做好一件事，哪件最可能改变结果？

不能只截取原回答的前两条，也不能把每一项都各缩一句后照单全列。工作量大、做过很多检查，不代表这些内容都值得进入重点。证据不足以判断优先级时，直接说最关键的未知是什么，不编造“只要做好这一点就一定成功”。

### 输出让用户能判断的最小充分内容

- 开头直接说最重要的结论或建议，通常一到两个要点；每点只保留理解它所需的简短理由。
- 若有会推翻建议的条件或未知，紧接相应要点用一句话说明。确有超过两个独立且不能遗漏的决定性问题时，可多写必要的一点，不为凑数量隐去风险。
- 需要用户取舍时，先给自己的推荐，再指出一个具体决定及主要代价，例如“我建议先验证新增模块有没有收益，再做大规模训练；现在需要你定的是先验证，还是直接投入完整训练。”仅在这项选择确实未确定且需要用户决定时提问。
- 不用“你怎么看”“是否满意”“要不要继续”充当决策问题。无需用户决定时直接结束；已经获准的工作继续执行，不借此模式增加审批或暂停。
- 次要解释和扩展建议先不展开，不在末尾追加长篇细节来抵消精简。用户要求完整材料时再提供；已有证据可用少量直接链接支撑关键结论。

本模式仍只作用于第二阶段。只要求压缩已有回答时，基于已有材料重新组织，不无故重做调研；新问题仍先正常完成分析。汇报变短不表示工作可少做。

## 发出前核对

确认组织后的回答仍忠实于第一阶段所得结果：没有新增未经查证的事实，没有把推断改成定论，没有遗漏会改变建议的条件，也没有数字、单位或比较对象错位。

用户应能扫到主要结论，并通过后面的解释明白理由。如果整理时发现关键证据缺失，回到第一阶段做必要补充；不要用更漂亮的措辞遮住缺口。不需要向用户展示内部推理逐字稿或为了本 skill 保存完整草稿。

## 个人习惯与更新

此 Skill 能持续更新，适配每个人的习惯；**默认不更新，只有使用者明确要求更新、修改本 Skill，或明确要求把某项偏好保存为长期规则时，才修改本地安装版本。** 用户只说“说人话”“短一点”“这次没看懂”时，按要求调整当前回答，不据此改写 Skill。

本版本不连接反馈库或蓄水池，不自动采集、保存对话，不调用反馈记录员，也不安排后台学习、更新或同步。每个人的偏好只作用于自己的安装版本；未经另外明确授权，不向共享仓库推送、不改队友的版本，也不改其他技能、项目规则或 Codex 记忆。

收到明确更新要求后，定位实际使用的安装文件，按本次要求做必要修改，保留无关内容，递增版本并检查文件可用性，简要说明改了什么。除非使用者明确要求改变，始终保留“正常完成研究，表达规则只作用于汇报组织”的约定。更新授权已明确时直接执行，不重复询问同一授权。
