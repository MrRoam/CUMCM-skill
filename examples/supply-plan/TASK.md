# 校园应急补给点：合成协作练习

这是纯合成（synthetic）数学建模案例，没有真实灾情、真实地点或个人信息。数据不是现实部署依据。

校园被划为12个不重叠需求组，每组人数见 `data.json`。6个候选点可服务不同需求组，一个人被多个点覆盖仍只计一次。每个点有固定年运营费用。最多选3点，至少覆盖700人，在此基础上让**每万元年运营费覆盖人数**尽量大。

假设：组内所有人均可被覆盖该组的点服务；服务能力无上限；不模拟时段、容量、道路阻断和个体差异。成本可直接相加。以上均为练习定义，未由现实观察验证。

## 需要交付

1. 明确目标、单位、约束和重叠的处理；给出一个可行方案。
2. 求目标最好的方案，并说明是否拥有最优性证据。不要把覆盖人数最大当成最终目标。
3. 保存选点、覆盖组、人数、年成本、单位成本覆盖表现以及复算方式。用简短文字解释选点理由及模型边界。

`supply.py` 是标准库参考评价器，支持直接评价、穷举和独立穷举核对。全部只有64个子集，不需要安装库或长期搜索。

```text
python supply.py evaluate --select A B C
python supply.py solve
python supply.py verify
```

输出写到标准输出；可用 `--output relative/path.json` 保存新文件，已有文件不覆盖。默认读取脚本旁的 `data.json`，换数据用 `--data PATH`。`verify` 用另一种逐需求组判断的独立实现检查全部子集。

## 手算检查（不是推荐答案）

选A、B、C：A与B共享G03、G04，不能把两点覆盖人数直接相加。三点并集是G01至G09，共710人；年成本40000+30000+28000=98000元，即9.8万元；目标为710÷9.8≈72.44898人/(万元/年)，满足练习的两项约束。这个可行方案不是对最优性的声明。

## 协作练习

一个任务维护数据与评价定义，一个任务寻找候选，一个任务接收结果并整理解释；这只是本次交付分工，不固定三个人的长期角色。文件更新后要用新版本复算，不能仅沿用旧结果名称。比较前确认数据、成本单位、最低覆盖、覆盖定义和指标口径一致。未取得结果前可以先写方法说明，不能预填最优数值。

模型或单位变化时，保留旧版作对照并说明新口径；不把两版不同口径的指标直接排高低。正式比赛仍由队伍理解、核验与决定，本练习中的代理协作不能冒充真人理解或三账号实测。
